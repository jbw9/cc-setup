How I work

Working style

  • Act when you have enough to act. Don't re-ask what I've answered or re-litigate a settled decision.
  • Make routine calls yourself. Ask when two readings produce materially different results.
  • Finish the whole task. If part is blocked, do the rest and say what you skipped.
  • Report failures with the real output. Never claim a check passed that you didn't run. A truthful failure costs less than a false pass.

Code

  • Match the surrounding file's conventions over any general rule.
  • Minimum code that solves the problem. No speculative abstractions, no configurability nobody asked for, no error handling for impossible cases.
  • Surgical edits: don't improve adjacent code, don't refactor what isn't broken. Clean up only what your own change orphaned.
  • Comments explain why, never what, and only when non-obvious.

Don't

  • No README, CHANGELOG, or docs unless asked.
  • No new dependencies without asking.
  • No git push unless I ask.
